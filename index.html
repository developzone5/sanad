SANAD · CHAIN OF PROOF FOR CLAUDE CODE

Nothing ships without a verified chain of proof.

Sanad (سند) — the authenticated chain that makes a narration trustworthy, rebuilt for code. One command, /sanad, runs one gated loop: understand, check facts, design, build and prove, independent review, gate, ship. Underneath sits an always-on rulebook and an automatic safety net.

01 / THE LOOP

One task, six moves

Every request enters /sanad. Questions get a direct answer; real implementation runs these six steps, each with one exit rule. The rulebook (CLAUDE.md) runs beneath all of them.

01
understand

Done means

3 to 8 checkable results in your words, including what must NOT change. Unclear? One question, not a guess.

02
facts

Check the facts

Every outside fact the design depends on is proven with a real sample, or written down as an open assumption you accept.

03
/braintrust

Design

Bounded work is routed directly. Uncertain or sensitive work gets a panel of specialists and one boss decision.

04
build

Build and prove

Red before green for a bug. Tests through the public entry point, the real provider when data writes change, run for real.

05
review

Independent review

A fresh read-only reviewer reads the frozen source for bugs, missed requirements and data or security risk. Exit: REVIEW: PASS.

06
/gate · /ship

Gate and ship

The gate runs once on the final source with real output. Then a short ship brief, a draft PR to a safe branch, and your explicit yes.

02 / SKILLS

The skills in detail

/sanad is always the entry point. The others are the steps it reaches for.

/sanad

sanad

The task loop itself. Classifies each request (teach, check, implement), routes implementation before any edit, then walks the six steps and talks in one line per stage.

Loop
/spec

spec

Keeps one living spec file per feature (goal, decisions, plan, risks, log), so a long feature stays on course across many sessions.

Plan
/braintrust

braintrust

For a tough call, it seats 2 to 6 specialists for the open questions (pragmatist, architect, skeptic, performance, product, database, security, authenticity). Each makes its case, then a separate boss reviews every report and gives one clear recommendation. Runs entirely on Claude, no API keys.

Decide
/gate

gate

Checks the change against my full Definition of Done and security list: builds, tests, security, and edge cases, with every claim backed by real command output.

Verify
/ship

ship

Writes a plain-language brief of the change (what, why, proof, impact), then opens a draft pull request on a safe branch, never straight to production, and waits for your approval.

Ship
full-output

full-output-enforcement

Guarantees complete, ready-to-paste code: no // ..., no TODOs, no skipped sections, even when the output runs long.

Complete
impeccable

impeccable

Designs and refines interfaces end to end: layout, typography, color, motion, accessibility, and right-to-left support, grounded in a real design system.

04 / GUARDRAILS

The safety net

Deterministic Node scripts. They stay out of the way until a rule is about to be broken.

policy-guard

Publishing guard

Publishing needs completed passing verification, a real evidence receipt, a finished reviewer run after the last change, then REVIEW: PASS and GATE: PASS. Protected branches and destructive commands are refused.

hooks/
precommit-guard

Secrets guard

Denies a commit that carries a hardcoded secret (new files included), a credential file, or an AI-attribution line. Plain script, no AI, no delay.

hooks/
stop-gate

Definition-of-Done gate

After a code change, missing, failed or pending verification blocks the turn once, then warns honestly. A dev server is not verification; a real test run is.

hooks/
csharpier · session

Format and state

Unformatted or partly staged C# files cannot be committed. Every session starts by printing branch, ahead/behind, uncommitted count and PR state.

hooks/
CLAUDE.md

The rulebook

Always-on: a professional engineering bar, the security gate, Definition of Done, git and PR flow, and a hard "be short by default" rule.
