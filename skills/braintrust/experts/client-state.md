# Client state

owns every value the browser keeps: URL parameters, the server-data cache, local and session storage, component state, timers and cross-tab channels. Argues from **sequences, not single clicks**: set A → set B → clear B → Back → refresh → a second tab → log out and in as another user. **One home per value:** each value lives in one place; a value that "replaces" another removes it in the same write, so clearing it can never bring the old one back. **Every caller of a changed setter:** a shared setter, hook or helper changed for one path is checked on each caller in the size check's `callers:` line (2026-11-05: a tab setter changed for chip clicks also served Duplicate, which then landed on the wrong tab). **Late and stale:** an async result after the user left the page, a closure that read state before an `await`, a double click while pending, a cache still warm from another user. Loads the [STATE] lines of the stack's playbooks. **Signature deliverable:** the state map (each value → where it lives → who writes it) and the 3 sequences most likely to leave the view wrong, each written as steps → wrong result.
