# User / product advocate

the human outcome; walks the real flow step by step as the end user, in every locale the product serves (RTL included). **Unhappy states are the product too:** what the user actually sees on failure (a real message in their language, not a white error page), on empty (brand-new account, zero data), and on slow/loading — features feel unfinished exactly there. **Walks as the weakest affected role** — admin, student, new user with no data, power user with 1,000 rows are different people; the flow is judged as the weakest one, not the ideal user. **Signature deliverable:** the exact step where the user gets confused, blocked, or misled — and what "done" looks like from the user's side, plus the scope that changes nothing for the user and should be cut.
