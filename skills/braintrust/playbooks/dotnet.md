# Playbook — .NET (ASP.NET Core + EF Core)

Load when the stack line names .NET. Versions come from the stack line; a line marked *(version)* depends on it — check before citing it. Tags name the owner: [SEC] Security, [DB] Database, [PERF] Performance, [STATE] Client state, [TEST] Test designer, [ALL] every seat and reviewer.

- [SEC] Every endpoint states who may call it: `[Authorize]` (roles or policy) or `[AllowAnonymous]`. Without a `FallbackPolicy` in `Program.cs`, an endpoint with no attribute is open to anyone.
- [SEC] Owned rows are loaded by id and owner/tenant in the same query (`Where(x => x.Id == id && x.SchoolId == scope)`). A row the caller does not own returns 404, not 403, so ids cannot be probed.
- [SEC] Bind requests to request DTOs, never to entities (over-posting). Responses are DTOs too: an entity serializes every field, including the ones the screen never shows.
- [SEC] Cookie auth plus a state-changing endpoint means anti-forgery (`[ValidateAntiForgeryToken]` or the global filter) and SameSite cookies.
- [SEC] Uploads: a size limit per endpoint (`RequestSizeLimit`, `FormOptions`), the type checked from content and not only from the extension, and a stored name generated by the server. Never `Path.Combine` a client file name.
- [SEC] Errors leave as `ProblemDetails` with a code, never exception text. Log once, at the edge.
- [DB] Read paths: `AsNoTracking`, project with `Select` into the DTO, no `Include` for read models, and no query inside a loop (N+1).
- [DB] Lists: a stable, unique order (`OrderBy(x => x.CreatedAt).ThenBy(x => x.Id)`); keyset paging for deep pages.
- [DB] `ExecuteUpdate` / `ExecuteDelete` skip the change tracker, interceptors (audit, soft delete) and concurrency tokens, unless the token is in the `Where`. *(EF Core 7+)*
- [DB] Contested rows carry a concurrency token; `DbUpdateConcurrencyException` becomes 409 with a code the page understands.
- [DB] Never edit an applied migration. Read the SQL it generates (`dotnet ef migrations script`). Backfills are set-based. A migration run at startup must converge when it dies halfway and runs again.
- [DB] A retrying execution strategy (`EnableRetryOnFailure`) refuses a transaction you open yourself, unless it runs inside `strategy.ExecuteAsync`.
- [PERF] Async all the way down: no `.Result` or `.Wait()`; pass the `CancellationToken` into every EF call.
- [PERF] A `DbContext` is scoped and not thread-safe: no `Task.WhenAll` over queries on one context.
- [PERF] Background work (`BackgroundService`) creates a fresh scope per unit of work. With more than one instance, an in-memory lock locks nothing: use a database lock, a unique key or a queue.
- [PERF] `IMemoryCache` is per instance; a cache key holds every input plus the user or tenant scope.
- [ALL] Server time is UTC (`DateTime.UtcNow`, `DateTimeOffset`); inject `TimeProvider` so tests control the clock. *(.NET 8+)*
- [TEST] The EF InMemory provider has no transactions, no constraints, no raw SQL, and compares strings like C# does (case-sensitive). Queries, unique rules and migrations get a test on the real database engine.
- [TEST] Every state-changing or owned endpoint gets negative tests: anonymous → 401, wrong role → 403, not owner → 404, missing anti-forgery → rejected.
